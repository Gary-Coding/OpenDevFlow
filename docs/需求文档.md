# OpenDevFlow 需求文档

## 1. 项目定位

OpenDevFlow 是一个开源、自托管的 AI 软件交付工作流平台，面向个人开发者、小团队和企业研发团队。

平台目标不是替代 IDE，而是提供从需求产出、规格固化、代码实现、QA 验收到 PR 交付的完整 AI 工作流。

OpenDevFlow 第一版基于 `biz-skill-hub` 技术骨架扩展，采用模块化单体架构，优先支持本地和私有化部署。

## 2. 核心目标

- 支持用户创建 AI 软件交付工作流。
- 支持项目、代码仓库、需求、规格、开发、测试、PR 的阶段化管理。
- 内置 OpenSpec 风格的规格产物管理。
- 吸收 Superpowers 风格的阶段纪律，包括 brainstorming、计划拆解、TDD、review、finish branch。
- 吸收 super-engineer-workflow 的开发交付能力，包括状态机、实施计划、验证、审查、归档。
- 提供 Web 工作流看板，而不是完整在线 IDE。
- 支持开源自托管，默认使用 PostgreSQL、FastAPI、Vue 3。

## 3. 非目标

第一版不做：

- 完整在线 IDE。
- 多人实时协同编辑。
- SaaS 计费系统。
- Kubernetes 多租户调度。
- 模型 marketplace。
- 本地文件实时同步。
- 完整 PM/QA 专家系统。

## 4. 用户角色

### 4.1 管理员

- 管理用户、角色、权限。
- 查看审计日志。
- 配置平台基础参数。
- 管理项目和仓库访问权限。

### 4.2 开发者

- 创建和推进 AI 交付工作流。
- 查看需求、规格、计划、代码变更、测试结果。
- 启动开发阶段 agent。
- 创建 PR 或输出交付报告。

### 4.3 审查者

- 审查 PRD、OpenSpec 规格、开发计划、QA 结论。
- 批准或驳回阶段流转。

## 5. 标准工作流

标准工作流阶段：

```text
Idea
-> Product Discovery
-> Product Review
-> Spec Authoring
-> Spec Review
-> Dev Planning
-> Implementation
-> Dev Review
-> Dev Verify
-> QA Planning
-> QA Verification
-> Final Review
-> PR Ready
-> Archived
```

每个阶段必须记录：

- 当前状态。
- 输入产物。
- 输出产物。
- 执行日志。
- 阻塞原因。
- 下一步允许动作。
- 是否需要人工审批。

## 6. 核心模块

### 6.1 项目管理

支持创建项目，项目包含：

- 项目名称。
- 描述。
- 默认代码仓库。
- 默认工作流类型。
- 成员权限。
- 审计记录。

### 6.2 仓库管理

第一版支持手工录入 Git 仓库信息：

- 仓库名称。
- Git URL。
- 默认分支。
- 本地 clone 路径或 workspace 路径。
- 仓库状态。

后续可扩展 GitHub/GitLab OAuth 和 GitHub App。

### 6.3 工作流管理

支持创建工作流：

- 选择项目。
- 选择仓库。
- 输入原始需求。
- 选择工作流类型：`new_feature`、`bugfix`、`refactor`。
- 自动生成 workflow 编号。
- 初始化阶段状态。

工作流详情页展示：

- 阶段看板。
- 当前阶段。
- 阶段产物。
- agent 执行日志。
- 审批状态。
- 阻塞原因。
- 下一步动作。

### 6.4 需求产物

Product Discovery 阶段产出：

- `prd.md`
- `user-stories.md`
- `acceptance-criteria.md`
- `scope.md`
- `open-questions.md`

第一版可以由用户手动编辑或由 agent 生成。

### 6.5 规格产物

Spec Authoring 阶段产出 OpenSpec 风格文件：

- `proposal.md`
- `design.md`
- `tasks.md`
- `specs/**/*.md`

平台需要支持查看、编辑、审批这些文件。

### 6.6 开发交付

Dev 阶段产出：

- `dev-plan.md`
- `implementation-report.md`
- `self-check.md`
- `code-review.md`
- `verify-report.md`
- `diff-summary.md`

开发阶段需要支持：

- 启动 agent run。
- 记录执行日志。
- 记录命令输出。
- 记录变更文件。
- 记录验证结果。
- 失败时进入 blocked 状态。

### 6.7 QA 验收

QA 阶段产出：

- `test-plan.md`
- `test-cases.md`
- `qa-report.md`
- `bugs.md`
- `acceptance-result.md`

QA 结论包括：

- `passed`
- `failed`
- `blocked`

只有 QA passed 后，才能进入 Final Review。

### 6.8 PR 与归档

Final Review 阶段支持：

- 展示最终 diff summary。
- 生成 PR 描述。
- 记录测试结果。
- 记录交付摘要。
- 标记 PR Ready。
- 归档工作流产物。

第一版可以先生成 PR 文案，不强制集成 GitHub API。

## 7. 数据模型建议

核心表：

- `projects`
- `repositories`
- `workflows`
- `workflow_stages`
- `workflow_artifacts`
- `agent_runs`
- `agent_run_logs`
- `workspace_sessions`
- `pull_requests`
- `audit_logs`

`workflows` 关键字段：

- `id`
- `project_id`
- `repository_id`
- `title`
- `type`
- `phase`
- `status`
- `branch_name`
- `created_by`
- `created_at`
- `updated_at`

`workflow_artifacts` 关键字段：

- `id`
- `workflow_id`
- `stage`
- `artifact_type`
- `file_path`
- `content`
- `version`
- `created_by`
- `updated_at`

`agent_runs` 关键字段：

- `id`
- `workflow_id`
- `stage`
- `agent_type`
- `status`
- `started_at`
- `finished_at`
- `exit_code`
- `summary`
- `blocker_reason`

## 8. 权限要求

沿用 `biz-skill-hub` 的 JWT + RBAC。

建议新增权限：

- `project:read`
- `project:write`
- `repository:read`
- `repository:write`
- `workflow:read`
- `workflow:create`
- `workflow:update`
- `workflow:approve`
- `workflow:run_agent`
- `artifact:read`
- `artifact:write`
- `audit:read`

## 9. 审计要求

以下操作必须写入审计日志：

- 登录。
- 创建项目。
- 创建仓库。
- 创建工作流。
- 修改工作流阶段。
- 审批阶段。
- 启动 agent run。
- 修改 artifact。
- 标记 QA 结果。
- 标记归档。

## 10. 技术选型

参考 `biz-skill-hub`：

- Frontend：Vue 3 + Vite + Pinia + Element Plus。
- Backend：FastAPI。
- Database：PostgreSQL。
- Auth：JWT + RBAC。
- Architecture：模块化单体。
- Deployment：Docker Compose。

后续可选增强：

- Redis：后台任务队列。
- Docker：隔离 workspace runtime。
- Supabase：可选托管 PostgreSQL / Storage，不作为默认核心依赖。
- GitHub/GitLab API：PR 创建和仓库授权。

## 11. MVP 范围

第一版必须完成：

- 用户登录。
- 项目管理。
- 仓库管理。
- 创建工作流。
- 工作流阶段看板。
- artifact 查看和编辑。
- workflow 状态流转。
- agent run 记录。
- 审计日志。
- PR 文案生成。
- 工作流归档。

第一版可暂缓：

- 真实容器 workspace。
- 自动 clone repo。
- 自动运行 Claude Code / Codex CLI。
- GitHub OAuth。
- 自动创建 PR。
- 实时日志 WebSocket。

## 12. 验收标准

MVP 验收条件：

- 管理员可以登录并管理用户权限。
- 用户可以创建项目和仓库。
- 用户可以创建一个 `new_feature` 工作流。
- 工作流可以按阶段推进。
- 每个阶段可以创建和查看对应 artifact。
- 阶段审批会更新 workflow 状态。
- agent run 可以被记录并显示日志。
- 所有关键操作写入审计日志。
- 工作流最终可以生成交付摘要和 PR 描述。
- 项目可以通过 Docker Compose 启动数据库。
- 前后端可以本地运行。
